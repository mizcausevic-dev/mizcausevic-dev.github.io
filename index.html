Buyer-Published Contract → Multiple Enforcement Points

One AI Procurement Decision Card drives four enforcement surfaces.

Decision Card v0.2 adds data_vault_targets[] — a Skyyflow-shaped field-level vault contract declaring which PII fields may be tokenized and which roles may detokenize. Decision Card v0.3 adds retention_envelope[] — per-field TTL + redaction action + ed25519-signed deletion-proof endpoint, the pair to vault targets: who can read AND how long the data lives. Four sibling repos implement the same SkyyflowVault interface across server-side, client-side, pipeline-side, and CLI. One buyer document, four enforcement axes.

SERVER-SIDE

rag-sentinel

Tokenize-before-index for RAG. PII is replaced with skyy_<hex16> tokens before content reaches the vector store. Detokenize gated by caller-role authorization on the rag-sentinel side, before the vault ever sees the request.
CLIENT-SIDE

deal-desk-workspace

RBAC-aware reveal for the deal desk surface. Sales Reps see masked tokens; Deal Desk Leads and Finance Directors may click-to-reveal. Every attempt — successful or denied — appears in a session audit panel.
PIPELINE-SIDE

kg-skyyflow-klaviyo-bridge

Node lib + CLI · audit · tokenize · detokenize · transform (webhook → Klaviyo). Per-field protection levels: none / masked / tokenized. v0.2.0, AGPL-3.0, 40 vitest tests, 95% coverage.
VISUAL

skyyflow-klaviyo-bridge-console

React + Vite operator console — dashboard with recharts, live webhook simulator with a 3-stage animated pipeline (ingress → vault → klaviyo), field mapper, sync log stream. Runs the real engine in-browser via Web Crypto.
